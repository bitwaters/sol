# 首次调参前的数据质量优化

> 宽范围研究整改与开发阶段按样本数量准入，以 [RESEARCH-REMEDIATION.md](RESEARCH-REMEDIATION.md) 为准。下文描述保留的旧测量体系；生产对照采样调度已切换为独立研究采样。

策略阈值保持原值。本次改变采样、回测与报告，不自动调参，不增加交易功能。
测量协议版本为 `measurement-2026-09-14.2`；交易规则版本及配置哈希另行记录。

## 已实施任务

| 顺序 | 工作 | 验证方式 |
|---|---|---|
| T1 | 新增基准质量、补价审计、期限行情来源、永久缺口表；幂等升级 | 旧库重复升级、缺口跨重启保留测试 |
| T2 | 对照保留原始抽样记录；仅接受 60 秒内且不晚于采样时间的价格 | 空价、过期价、未来时间戳测试 |
| T3 | 有界后台补价；历史样本只用采样前已完成 K 线；恢复缺基准任务 | 历史容差、API 异常、重试、基准竞争测试 |
| T4 | 固定窗口、原始/有效票、来源、风险、持仓、过滤结果及版本 | 实时报价后窗口重算、缺失特征不伪造测试 |
| T5 | 统计区分实时、历史重建、旧版未知、待补基准；分母只含到期样本 | 成熟度、独立代币及错误分类测试 |
| T6 | 只读单参数比较入口，时间留出与代币去重，质量不足拒绝结论 | 首次失败样本不可替换、样本不足拒绝测试 |

## 价格与时间

每 15 分钟按当前交易过滤及聚类规则保留接近门槛的对照候选，默认 2 票。
启动时及每 30 秒检查持久化的采样时间门槛，重启不重置 15 分钟间隔。
先写入抽样记录和完整的本地特征，价格缺失不会删除候选。
新对照在原抽样后 120 秒内可以进行后台实时报价。报价完成后，重新计算最新窗口，仍满足原始票数条件才将窗口、特征及基准时间一起更新。
`selection_ts` 及 `initial_features` 保留原始抽样意图；`anchor_ts` 和 `features.sampledAt` 记录完成后的测量时间。失去票数条件或超过 120 秒时，保留原始时间并转用历史重建。

历史重建使用 1 分钟 K 线，选择收盘不晚于原基准时点、距离不超过 120 秒的最近一根。不会使用今天的价格或画像冒充历史状态。零或无效基准价不能计算倍数；期限终点为零则是有效结果。
每次补齐记录新旧基准时间、价格、取价时间、偏差、方法和修复时间。历史方法的价格时间是实际 K 线收盘时间；实时方法使用本地缓存/请求时间标记，不宣称是交易所行情更新时间。
历史重建与旧版不完整特征只用于描述，不进入实时调参样本。

已推送信号仍以首次成功发送时间和发送价为基准。新候选及首次发送记录版本和特征；发送前后的基准转换会撤销原回测结果及重试状态。
旧记录无法核验的价格时间、画像和配置保持未知，不追认。

## 资格与完整性

对照资格使用正式钱包及代币校验器，只在分析副本中将“触发最低票数”和“校验最低有效票数”同时设为对照票数；生产配置不变。
其他门槛继续生效，包括净流入、建仓、聪明钱、可核验持仓、风险与追高条件。
画像（与正式评估共用 30 分钟 TTL）、价格、风险、基础资料缺失或过期的样本不具备可比资格。
`features.eligible` 表示当次分析资格，不能替代实际发送结果。

新缺口记录全部保留，包括后来补齐的区间及按不可观测接受的区间。
样本窗口与任何来源的缺口重叠时保守排除，即使该缺口后来恢复。
升级时仅导入旧库仍保存的最近接受缺口，升级前完整缺口历史不可恢复；覆盖起点之前的窗口一律标为未知。

## 调度和失败状态

每 30 秒启动一个不重叠的测量批次，最多补 4 个基准、评估 4 个样本；每个样本最多三个到期期限。
GMGN 使用原共享限流器、原封禁门及总预算。后台另限最多每秒 1 个权重、单并发；冷却完成后按到达顺序排在已有请求后，不要求前台队列完全空闲，避免持续饥饿。等待最多10秒，超时安全撤销且不允许后续请求越过前序请求。全局封禁期间停止后台请求。
对照报价不写共享 token 缓存，避免覆盖正式评估的并发更新。

- 基准没有合适 K 线：间隔至少 5 分钟，三次后标记耗尽，记录仍在分母中。
- 期限没有合适 K 线：间隔至少 5 分钟，三次后该期限耗尽。
- 网络或 API 请求错误：保留可恢复状态，5 分钟后重试，不消耗缺行情次数。
- 排队超过10秒或 GMGN 封禁：跳过后台任务，不消耗缺行情次数。
- 只有缺失/无效基准成功修复后才重置其期限任务；不会清空有效基准样本的行情耗尽状态。
- 所有异步写入前核对原基准，避免覆盖发送等流程期间产生的新基准。

## 统计口径

`/stats` 及每日报告分组展示：总样本、独立代币、各期限已到期/未到期、有效结果、独立有效代币、缺基准、缺行情、待评估/重试、重试耗尽与覆盖率。
覆盖率 = 有效结果 / 已到期样本，未到期不计失败。
“缺行情”与“待重试/耗尽”有交集，不可相加。
历史统计的全量中位数仅作价格描述，不作为混合版本调参依据。

## 离线入口

在服务器当前已部署容器内运行（只读，不读取或输出密钥、钱包地址、原始响应）：

```sh
docker exec sol-bot-1 node dist/ops/tuning-report.js /app/data/meme.sqlite validVotes 3
docker exec sol-bot-1 node dist/ops/tuning-report.js /app/data/meme.sqlite marketCap 50000
docker exec sol-bot-1 node dist/ops/tuning-report.js /app/data/meme.sqlite ageMinutes 60
```

每次预先指定一个比较轴，输出阈值两侧的价格变化描述。有效票数轴对应两个联动票数门槛。
不能用该入口验证 5/15/30 分钟窗口或改变交易金额门槛：那需要从归档事件进行完整反事实重放，目前入口会拒绝这些参数。

按配置、规则、测量版本、来源组合分组；只让实时且特征完整、窗口无缺口的样本参与比较。
先按代币保留首次样本，再筛选质量及结果，不能用后来成功结果替代首次失败。
同币不会跨训练与留出组；按时间排序后，按样本数量前 70% / 后 30% 划分。
训练期选择的轴和阈值应冻结，查看留出结果后不能继续反复挑选并宣称独立验证。

拒绝调参结论的门槛包括：

- 新对照实时基准价覆盖率不足 95%（同时检查所在版本与来源组）；
- 有效独立对照代币不足 20 个；
- 到期 1 小时覆盖率不足 90%；
- 训练/留出中，阈值两侧任一格少于 20 个有效独立代币或覆盖率不足 90%。

20 个对照只是下限，不代表其他门槛已通过。达到门槛也仅允许描述性比较，不证明收益优势；手续费、滑点、容量及独立样本验证仍不可缺。

## 部署和回退

部署前使用 SQLite 一致性备份并验证 `quick_check`。仅通过本地提交 → GitHub → SEA 快进部署更新代码。
数据库升级只增加表，旧代码忽略新表；正常回退优先回退应用镜像，保留运行数据。
若必须恢复数据库备份，需要先停止服务并评估会丢失的后续成交及 Telegram 投递记录，不能直接覆盖活动数据库。
线上验证应报告修复的实际数量和剩余状态，不把“代码已完成”当成“样本已达标”。

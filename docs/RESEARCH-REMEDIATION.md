# 宽范围研究、规则比较与离线回放

本版协议 `research-2026-09-14.1`。用户要求开发阶段按样本数量准入，不设置 14 天或任何最短运行天数。期限行情仍需等到实际到期，不能把尚未发生的 1 小时/24 小时结果当作有效结果。

## 交付范围与数据口径

| 任务 | 实现 | 验收依据 |
|---|---|---|
| T1 研究配置独立 | `research.json`、`research/config.ts`；配置哈希和测量协议同时记录 | 研究配置与生产配置分开；生产规则版本不变 |
| T2 全部规则诊断 | `research/diagnostics.ts` | 原始值/上下限/通过/失败/未知/不适用；钱包可同时命中多个原因；后续汇总不因前一条失败而停止 |
| T3 冻结状态 | `research/snapshot.ts`，压缩保存在研究表 | 原始入选与完成时点快照分别保留；包含事件及来源到达时间、画像、持仓、检查点、当时观察次数、缺口、黑名单及配置 |
| T4 扩大采样 | `research/collector.ts` | 最近60分钟有正金额买入的已观测SOL代币，按原始买入地址数1/2/3/4/5+分层；不沿用300美元、3票、市值等筛选条件 |
| T5 有界富化 | 共用 `gateway.background()` | 前台预算、封禁、排队机制不变；研究不写共享画像/代币缓存，记录排队和富化失败 |
| T6 独立实验 | `research/replay.ts`、`research/report.ts` | 同一快照原规则与单因素方案对比；原规则失败但新规则通过的对象可进入“新增组” |
| T7 报告 | `/stats`、每日统计及两个CLI | 研究与旧版分开，数量/覆盖率/逐条拦截/缺资料原因；分层入选概率可审计 |
| T8 事件和状态回放 | 内存SQLite重建，调用正式窗口/聚类/钱包/代币校验器 | 窗口最大60分钟；金额、动作、画像门槛、关联参数可重算；更改来源/尘埃阈值时须具备可靠起点 |
| T9 投递回放 | 执行前有界冻结，内存运行真实候选/退出/Pusher实现及假发送器 | 支持静默、限速、TTL、编辑、冷却、退出门槛；可指定成功/429/结果未知情景，不产生真实消息 |
| T10 路径和成本 | `research/outcomes.ts`、`research/cost.ts` | 已完成K线端点、收盘路径完整率、收盘最大回撤、明确输入的成本情景 |

范围是**已采集到的SOL交易及被抽取的观察时点**，不是全市场、全部历史时点或连续策略回测。只有快照和事件证据足够的样本才可回放；其余明确标记不可验证，不用当前资料补造历史。

## 采样、预算和存储

- 默认每300秒检查一轮，5个地址数层各最多1个代币，共最多5个；重启保留采样时间。地址数分层只决定抽样，分析另算聚类前后和过滤前后票数。
- 同层按版本、采样时间和代币的稳定哈希排序，入选概率为该层实际入选数/候选数。队列容量不足时轮换层的优先顺序；报告保留各层总体数与入选数。这里的权重只描述实际抽样总体，不代表全市场。
- 待处理最多24个，每30秒处理最多2个新样本、2个到期结果；新样本每次最多补2个缺失/过期钱包画像。共用每秒最多1权重的后台预算及原全局预算，繁忙即让路。
- 新样本允许120秒内完成富化。此时重新冻结整个窗口、状态及基准时间，原始入选快照保留。超过期限沿用原始快照，不使用后来的报价或画像。
- 基准价缺失的研究样本保留在分母，本版不把历史补价标成实时研究样本。原测量体系的历史补价功能继续运行。
- 单样本最多5000条保留成交、100个钱包；超过上限记录 `snapshot_size_limit`，不静默截断成“完整样本”。压缩快照独立存储在运行数据库中，不受成交30天清理影响。
- 投递快照保留同币历史投递及成员绑定，避免回放遗漏去重状态。仅在有待执行任务时记录，同任务状态每分钟最多一份；最多200个任务、4个代币、1000个相关信号，压缩后最多2MB。超过限制保留失败计数。此范围不承诺捕获所有可能状态。
- 研究数据随数据库一致性备份，原始响应、画像、地址、聊天标识及快照不得进入GitHub或公开报告。CLI输出仅汇总。

## 判定和比较

“输入完整”不要求所有策略通过。缺少成本依据导致某个派生指标不可计算时，该项标为未知；若实验改变条件后具有成本依据，则可重新判断，不能直接用零代替。

原配置每条校验独立记录。后续发现与样本窗口重叠的历史缺口也会撤销比较资格，冻结的策略输入仍保持原样。为了计算后续持仓、聪明钱等汇总，研究使用不改变钱包剔除条件的分析副本，去掉前置汇总门槛；生产校验器结果也同时记录，供一致性检查。

实验改变一个因素；有效票数联动两个下限。结果分成：原规则与实验均通过、仅实验通过（新增）、仅原规则通过（移除）、均不通过。比较报告将前者作为保留组，新增/移除作为变化组。全部不通过的对象仍在诊断报告中，但不当作被修改规则单独造成的差异。

- 同一代币先按**首次入选**去重，再判断数据质量；首次失败不会被后续成功替换。
- 按生产配置、规则、研究版本和来源组合分别比较。报告给出普通中位数及按抽样概率加权的中位数，两者都只适用于已抽样总体。
- 未注册实验可以立即查看探索性比较，按时间排序后的样本数量70%/30%分组，没有日历天数门槛。
- 正式留出验证先注册参数和值，固定当前最大样本ID作为边界。注册后新入选且此前未出现的代币才是留出样本；不允许更改注册定义后复用原ID。
- 准入：至少20个有效独立代币；训练/留出各自的保留组、变化组，每格至少20个有效独立代币；每格到期1小时覆盖率至少90%；整体及该版本来源组实时基准覆盖率至少95%。没有固定天数限制。
- 达标仅意味着可检查描述性差异，不自动修改生产配置，也不证明收益优势。反复试验、分组太细或几乎没有差异都可能导致结论不足。

旧版 `compareSamples` 也移除了14天门槛，改为按时间排序后的数量70%/30%分组；历史/旧版样本继续保持原资格，不能混入新研究组。

## 离线命令

在已部署容器内执行；路径为运行数据库。`overview`、`compare`、回放和成本命令只读；`register` 仅写实验定义，不修改生产配置。

```sh
node dist/ops/research-report.js /app/data/meme.sqlite overview
node dist/ops/research-report.js /app/data/meme.sqlite compare validVotes 2
node dist/ops/research-report.js /app/data/meme.sqlite compare netInflow 1000
node dist/ops/research-report.js /app/data/meme.sqlite compare windowMinutes 30
node dist/ops/research-report.js /app/data/meme.sqlite register validVotes 2
# 将返回的ID代入：
node dist/ops/research-report.js /app/data/meme.sqlite compare validVotes 2 EXPERIMENT_ID
node dist/ops/research-replay.js /app/data/meme.sqlite delivery '{"parameter":"maxPerMinute","value":10}' success 0
node dist/ops/research-replay.js /app/data/meme.sqlite delivery '{"parameter":"ttl","value":90}' 429 100
node dist/ops/research-replay.js /app/data/meme.sqlite cost '{"notionalUsd":100,"buySlippage":0.01,"sellSlippage":0.01,"buyFee":0.005,"sellFee":0.005,"networkUsd":0.01}'
```

支持的研究轴以 `research/replay.ts` 的白名单为准；配置结构及联动约束仍须合法。上述数值仅展示调用方法，不是已验证推荐参数。

## 回放与价格限制

- 窗口、金额、聚类等回放在同一已冻结观察时点重新计算，不据此宣称还原了改规则后“首次会在何时触发”。
- 尘埃阈值重放须有早于已保存成交的可靠零余额检查点。来源过滤重放须从已观测、无缺口的代币创建起点开始，且起点在冻结覆盖范围内；无法确认时拒绝重算，避免混入其他来源的余额证据。
- 投递回放使用真实执行器与假发送器，所有写入只发生在内存库。需要未记录的新行情/画像时禁止联网并标记不可验证；指定时间推进也不会生成该期间的新成交。成功/429/结果未知是人为指定的传输情景，不是对Telegram实际结果的预测。
- 研究端点5分钟/1小时使用1分钟K线，24小时使用5分钟K线；收盘不得晚于目标时间，偏差最多一个周期。零终点价格有效；缺行情每隔至少5分钟重试，三次耗尽；网络错误和后台繁忙不消耗缺行情次数。
- 路径单独核对蜡烛连续性，缺路径不伪装完整回撤。最大涨跌和回撤基于收盘，不能代表蜡烛内极值。
- 成本报告显式指定交易金额、双边滑点、手续费和网络费，使用固定期限退出的假设，不含成交容量、实际成交及可卖性验证；不是实盘收益率。

## 发布验收

本地测试与review修复 → GitHub提交推送 → SEA检查无意外修改并快进部署 → 只读检查研究采样、正式采集、推送状态、日志和数据库完整性。保持用户此前授权的正式Telegram运行模式，不增加研究信号推送。

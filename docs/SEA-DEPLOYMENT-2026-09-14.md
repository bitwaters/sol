## 按 GitHub 流程修复的问题

首次部署暴露了真实入口与小规模联调脚本的差异：启动后每个历史代币都触发异步富化，短时间并发过多；封禁期间等待中的调用又提前消耗额度，解禁时集中发送，导致持续限流。

处理全在本地完成并通过 GitHub 推送、SEA 快进拉取：

1. 没有已有候选或推送时，先按本地窗口内达到单笔金额门槛的买入钱包数做上界筛选；明显达不到票数门槛的代币不发起远端富化。
2. 跨代币评估最多并发 2 个，同代币更新合并排队。
3. 排队期间出现封禁时，解禁后重新获取额度，不能使用封禁期间累积的额度形成突发。
4. 突发容量降为 5；本地准备的 SEA 保密配置使用每秒 10 权重，为采集与富化留余量。
5. 镜像构建仅调整数据目录所有权，避免对全部代码和依赖递归 chown。
